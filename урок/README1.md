## 2️⃣ ЧТО ТАКОЕ LiDAR

> "LiDAR — это сенсор, который измеряет расстояние до объектов с помощью лазера."

**Формула:**

```
Расстояние = (скорость света × время) / 2
```

**Пояснение:**

- Лазерный луч выходит из сенсора
- Отражается от объекта
- Возвращается обратно
- По времени полёта вычисляется расстояние

## 📐 Как из данных получаются точки

<img width="376" height="367" alt="1-s2 0-S0263224125023164-gr15" src="https://github.com/user-attachments/assets/44e2a8f1-27c7-43eb-a002-b8afd1bed389" />

<img width="320" height="320" alt="A-scanning-matching-technique-based-on-2D-lidar-in-which-the-relative-transformation_Q320" src="https://github.com/user-attachments/assets/15d118fc-ec4a-47a3-bbdb-14b1517d2ee1" />

Лидар даёт **расстояние** и **угол**. RViz рисует **x** и **y**.

**Формула:**

```
x = distance × cos(angle)
y = distance × sin(angle)
```

**Пример:**

```
Стена на 2 м под углом 0°:
x = 2 × cos(0°) = 2.0
y = 2 × sin(0°) = 0.0

Точка: (2.0, 0.0) → стена прямо перед лидаром
```

**Итог:** каждая красная точка в RViz = результат этого преобразования.

## 🔌 Как лидар передаёт данные (До запуска драйвера)

> "Прежде чем запустить драйвер, давайте поймём, что происходит на физическом уровне."

1. **Подключение:** RPLIDAR A1 подключается к компьютеру через USB и определяется как последовательный порт (например, `/dev/ttyUSB0`).
2. **Поток данных:** Лидар непрерывно отправляет «сырые» байты по этому порту. В них зашита информация об угле и расстоянии до объектов.
3. **Важно:** На этом этапе данные **нигде не сохраняются в файл**. Они существуют только как поток байтов в памяти компьютера.

> "Именно для того, чтобы превратить этот «сырой» поток в понятные ROS-сообщения, нам нужен драйвер, который мы сейчас запустим."

## 🧠 Что такое Node и Topic (простыми словами)

> "Прежде чем говорить о драйвере, давайте поймём два главных понятия в ROS."

**Node** — это код на C++ или Python, который выполняет определённую функцию. Он может публиковать данные в топик или получать их из топика.

**Topic** — это канал, через который узлы обмениваются информацией.

**Пример:**

```
rplidar_node ──→ /scan ──→ hector_mapping
(публикует)      (топик)     (подписан)
```

> "Один узел публикует данные в топик. Другой узел подписан на этот топик и получает данные."

## 🔧 Как работает драйвер лидара

> "Драйвер лидара — это узел (node) в ROS, написанный на C++. Он получает сырые данные по USB и превращает их в понятный для ROS формат."

**Что содержит код драйвера (`node.cpp`):**

| Компонент | Что делает |
|-----------|------------|
| Подключение к USB | Открывает порт `/dev/ttyUSB0` |
| Чтение данных | Получает сырые байты от лидара |
| Парсинг | Преобразует байты в расстояния и углы |
| Публикация | Отправляет данные в топик `/scan` |

**Ключевые строки кода (показать):**

```cpp
// Подключение к лидару
drv->connect(_channel);

// Чтение данных
drv->grabScanDataHq(nodes, count);

// Публикация в топик
pub->publish(scan_msg);
```

## 8️⃣ HECTOR SLAM — КАК РАБОТАЕТ


**Ключевые особенности:**

| Особенность | Значение |
|-------------|----------|
| Нужна одометрия? | ❌ Нет |
| Метод | Scan matching (Gauss-Newton) |
| Работает с | RPLIDAR, ручное сканирование, дроны |
| Публикует | `/map`, `/tf`, `/slam_out_pose` |

**Цикл работы:**

```
1. Взять текущий скан из /scan
2. Сравнить с уже построенной картой
3. Найти лучшее совпадение (Gauss-Newton)
4. Обновить карту
5. Повторить
```

**Схема:**

```
/scan → Сравнить с картой → Найти совпадение → Обновить карту → /map
```

## 9️⃣ HECTOR SLAM — ЧТО ВНУТРИ


**Что содержит код:**

| Компонент | Что делает |
|-----------|------------|
| Подписка на `/scan` | Получает лазерные сканы |
| Scan matching | Сравнивает с картой |
| Gauss-Newton | Находит лучшее совпадение |
| Публикация `/map` | Отправляет карту |

**Ключевые строки кода (показать):**

```cpp
// Подписка на сканы
scanSubscriber_ = node_.subscribe(scan_topic_, 1, &HectorMappingRos::scanCallback, this);

// Публикация карты
mapPublisher_ = node_.advertise<nav_msgs::OccupancyGrid>("map", 1);
```




## 🔟 TF — СВЯЗЬ КООРДИНАТ


**Команда:**

```bash
rosrun tf static_transform_publisher 0 0 0 0 0 0 map laser 100
```

**Что означает:**

| Параметр | Значение |
|----------|----------|
| `0 0 0` | Позиция (x, y, z) — лидар в точке (0,0) |
| `0 0 0` | Поворот (yaw, pitch, roll) — без поворота |
| `map` | Родительская система координат |
| `laser` | Дочерняя система координат |
| `100` | Обновление каждые 100 мс |

**Почему без TF не работает:**

```
Без TF:
Лидар: "Я вижу стену в 2 метрах!"
RViz: "2 метра от ЧЕГО? Не знаю, где ты!" ❌

С TF:
Лидар: "Я вижу стену в 2 метрах от laser!"
TF: "Лидар находится в точке (0,0) карты"
RViz: "Ага! Стена в точке (2,0)!" ✅
```

## ⚠️ Возможные проблемы

| Проблема | Решение |
|----------|---------|
| `Permission denied` на `/dev/ttyUSB0` | `sudo chmod 666 /dev/ttyUSB0` |
| Карта не появляется | Fixed Frame = `map` |
| Карта не обновляется | Двигать лидар медленнее |
| TF не работает | Проверить, что команда запущена |
